## Navigation kit (nl-nav.js)
Every page that includes `accessibility.js` automatically gets, with no other edits:
- a slim vertical reading-progress rail on the right (percentage, draggable handle)
- Back to top / Go to bottom buttons

New HTML pages: copy the `<script src="accessibility.js"></script>` line from any existing page. That is all.

Long MCQ lists: use `NLNav.pager({...})` (range chips + pagination) and `NLNav.practice(el)` (attempted-questions bar).
Any long element can also be followed by the rail with the attribute `data-nl-track`.
Mock tests only get the rail and jump buttons; their engine is untouched.


## Installable app (PWA)
See PWA.md. New HTML pages: add `<link rel="manifest" href="manifest.json">` in `<head>` and `<script src="pwa.js" defer></script>` before `</body>` (copy from any page).


## Reading watermark (watermark.css)
A faint diagonal "NETLAWVERSE.IN" pattern sits over every question surface (unit-page MCQs, question bank cards,
quiz overlay incl. its review, timed test, mock-test questions and review, app practice / test / review).
It is CSS only: no JavaScript, no per-question markup, so new questions and new quiz packs are covered automatically.
- New page with questions: add `<link rel="stylesheet" href="watermark.css">` after the other stylesheets (copy from any page).
- New question container class: add its selector to the host list at the top of `watermark.css` (the list appears in the rules as `:is(...)`).
- Strength: `:root{--wm-fade:1}` (0 = off, 1 = default, 1.5 = stronger). High-contrast themes automatically use 60% of this.
- Colours follow `<html data-mode>` so every theme in light and dark is covered.
- `m-app.js`: the app's mock-test question body is wrapped in `<div data-wm>` so it has something to attach to.


## Share kit (nl-share.js)
Share buttons for the site, pages, questions, mock tests, scores and dohas, with rich link previews. See SHARE.md. New HTML pages: copy the `nl-share.js` script line from any existing page.


## Study notes (/notes/): generated from structured data
Chapter overview + one page per topic (sub-topics as anchored sections), right-hand contents tree, breadcrumbs, related topics, revision mode, studied ticks, search, rapid-recall sheet, JSON-LD and sitemap entries are all generated by one script. No server build step: the output is plain HTML in `notes/`.

    pip install markdown
    python3 _tools/build_notes.py        # run from anywhere; rewrites notes/ and the notes block in sitemap.xml

Two content formats are supported (set `"format"` in chapter.json):
- default (Research Aptitude): `## TOPIC 1A` > `### 1A.1` with **Concept / Memorise / Analyse / traps** per sub-topic.
- `"format": "chapters"` (Teaching Aptitude): `## Chapter 1: Title` > `### 1.1 Section` as ordinary prose, lists and tables, plus `### Memory Capsule: Chapter N` and `### Analysis Angle: Chapter N` at the end of each chapter. "Chapter N" mentions become links to the topic page. The rapid-recall page is built from the list sections named in `"rapid_from"` (for example `["10.5","10.2","10.3"]`). Optional chapter.json keys: `how` (the "How to use" steps) and `rapid_placeholder`.
  Convert the .docx with `pandoc file.docx -t gfm --wrap=none -o content.md`.

Add a new chapter (e.g. Comprehension):
1. Make `_notes-data/<paper>/<chapter>/` containing
   - `content.md`: your .docx converted with `pandoc file.docx -t gfm --wrap=none -o content.md`. Same pattern as Research Aptitude:
     `## TOPIC 1A – Title`, then `### 1A.1 Sub-topic title`, then `**Concept.**` paragraph, `**Memorise.**` bullets (or a table), `**Analyse / traps.**` paragraph.
     An optional `## RAPID-RECALL SHEET` section with a two-column table builds the rapid-recall page.
   - `chapter.json`: copy the Research Aptitude one. Set paper/unit/slug/name/unit_page/mcq_base/updated/description, list the modules and, per topic id, a `slug`, `mcq` links and `related` topics with a one-line reason. Optional per topic: `seo_title`, `description`, `lead`.
2. Run the script. The hub page, sitemap and search index pick the chapter up automatically.
3. Link to the chapter from the old unit page (see the "Detailed study notes" block in ugc-net-paper-1-unit-2-research-aptitude.html).
Styling is in `notes.css`, behaviour in `notes.js` (both use the existing theme tokens). Reader progress is stored only in the reader's browser (localStorage key `nl-notes-v1`).
